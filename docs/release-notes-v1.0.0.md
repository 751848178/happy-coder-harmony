# Happy Coder Flutter 1.0.0 新版本特性及测试说明

更新日期：2026-03-23

## 版本概述

本版本聚焦于鸿蒙发布前的功能收口、终端连接流程优化与基础稳定性提升。对外能力围绕“会话”和“设置”展开，便于先完成核心场景验证和受控发布。

## 新版本特性

### 1. 核心功能收口，界面更聚焦

当前版本仅保留以下对外能力：

- 会话
- 设置 -> 扫描二维码连接终端
- 设置 -> 手动输入终端链接
- 设置 -> 机器
- 设置 -> 账户 -> 服务器地址
- 设置 -> 账户 -> 退出登录
- 设置 -> 账户 -> 清除本地数据
- 设置 -> 关于

本次同步隐藏了收件箱、功能开关、更新日志、语音助手、备份恢复密钥、连接电脑等非当前发布范围内的入口，降低用户认知成本，避免未完成能力提前暴露。

隐藏能力清单详见 [hidden-features.md](/Users/zhaoxingbo/Workspace/ai-driven/happy-coder-flutter/docs/hidden-features.md)。

### 2. 支持两种终端连接方式

设置页提供两种终端接入方式：

- 扫描二维码连接终端
- 手动输入终端链接

用户可以直接通过电脑端提供的授权二维码或授权链接完成连接，适合现场演示、内部测试和受控分发场景。

### 3. 终端连接完成后自动同步状态

终端连接成功后，应用会自动执行以下同步动作：

- 强制刷新会话列表
- 拉取机器列表
- 重新初始化 Socket 连接
- 刷新远端会话消息快照

这样可以减少“连接成功但首页数据未及时更新”的情况，提升首次接入后的可用性。

### 4. 认证流程稳定性增强

针对账户授权和终端授权场景，本版本补充了认证态恢复与重试能力：

- 在授权响应遇到令牌失效时，尝试基于本地保存的密钥刷新认证信息并重试一次
- 在账户绑定或终端连接成功后，优先恢复并使用本地持久化后的最新认证信息

这可以降低连接过程中因 token 过期或状态未同步导致的失败概率。

### 5. 账户设置页简化为发布必需项

账户页当前仅保留以下发布阶段必需能力：

- 服务器地址
- 清除本地数据
- 退出登录

页面结构更清晰，也更适合当前阶段的运维、环境切换和问题排查。

## 测试重点

本版本建议重点验证以下四类场景：

- 核心功能入口是否符合当前发布范围
- 终端连接流程是否顺畅
- 连接成功后会话和机器信息是否正确刷新
- 账户相关高风险操作是否符合预期

## 测试说明

### 一、安装与启动

测试目标：
确认安装包可正常安装，应用可正常启动，无闪退或白屏。

测试步骤：

1. 安装测试包。
2. 启动应用。
3. 观察首屏加载与导航展示。

预期结果：

- 应用可正常安装和启动
- 首屏无明显卡死、白屏、闪退
- 首页仅保留“会话”和“设置”两个主入口

### 二、设置页可见性检查

测试目标：
确认当前发布范围内保留的功能可见，其他功能入口均已隐藏。

测试步骤：

1. 进入设置页。
2. 检查是否展示以下入口：
   - 扫描二维码连接终端
   - 手动输入终端链接
   - 机器
   - 账户
   - 关于
3. 检查以下入口是否已隐藏：
   - 功能开关
   - 使用统计
   - 更新日志
   - 语音助手
   - Claude Code
   - 个人资料
   - 其他未纳入本次发布范围的入口

预期结果：

- 设置页只出现当前保留的入口
- 不应出现已隐藏的设置项或其入口按钮

### 三、扫码连接终端

测试目标：
确认扫码连接终端流程可正常完成。

测试步骤：

1. 在设置页点击“扫描二维码连接终端”。
2. 使用摄像头扫描电脑端展示的授权二维码。
3. 等待连接结果反馈。

预期结果：

- 能正常拉起扫码页
- 识别成功后自动回填授权信息
- 连接成功后弹出成功提示
- 返回首页后会话列表与机器列表可刷新到最新状态

### 四、手动输入终端链接

测试目标：
确认手动输入授权链接的连接流程可正常完成。

测试步骤：

1. 在设置页点击“手动输入终端链接”。
2. 粘贴电脑端提供的授权链接。
3. 提交连接。

预期结果：

- 输入合法链接后可正常发起连接
- 无效链接时有明确错误提示
- 连接成功后返回会话页
- 会话、机器及远端消息快照会被自动刷新

### 五、机器列表展示

测试目标：
确认设置页中的机器列表可正确展示在线状态与基础信息。

测试步骤：

1. 完成一次终端连接。
2. 进入设置页查看“机器”分组。
3. 点击某一机器项进入详情页。

预期结果：

- 已连接机器可正常出现在列表中
- 在线/离线状态展示正确
- 机器名称、主机信息或路径信息展示合理
- 可进入对应机器详情页

### 六、账户设置检查

测试目标：
确认账户页仅保留当前发布范围内的必要能力，且操作可用。

测试步骤：

1. 进入设置 -> 账户。
2. 检查“服务器地址”“清除本地数据”“退出登录”是否存在。
3. 检查以下入口是否不存在：
   - 生成连接二维码
   - 扫码连接设备
   - 连接电脑
   - 备份恢复密钥
   - 当前设备信息卡

预期结果：

- 页面仅展示当前保留的账户能力
- 未登录时不应错误展示需登录后才可操作的退出登录项

### 七、服务器地址配置

测试目标：
确认服务器地址可查看、修改并生效。

测试步骤：

1. 进入设置 -> 账户 -> 服务器地址。
2. 查看当前配置值。
3. 修改为测试环境地址并保存。
4. 返回后重新进入确认值是否保留。

预期结果：

- 可正常打开服务器地址配置页
- 保存后配置持久化成功
- 重启应用后配置仍保留

### 八、清除本地数据

测试目标：
确认清除本地数据能力可用，并能清空本地缓存状态。

测试步骤：

1. 在已登录且已有本地数据的情况下进入设置 -> 账户。
2. 点击“清除本地数据”。
3. 确认操作并重启应用。

预期结果：

- 有明确二次确认
- 清理完成后本地缓存、会话缓存或本地认证状态按设计被清除
- 应用重启后不会残留异常旧状态

### 九、退出登录

测试目标：
确认退出登录流程完整且安全。

测试步骤：

1. 在登录状态下进入设置 -> 账户。
2. 点击“退出登录”。
3. 确认退出并返回首页或登录态页面。

预期结果：

- 退出操作有明确确认提示
- 退出后登录态被清理
- 退出后不应继续显示依赖已登录状态的会话内容

### 十、异常与回归验证

测试目标：
确认主要异常场景下应用行为可控。

建议补充验证：

- 未登录时尝试连接终端，是否能给出明确提示
- 输入非法终端链接时，是否能给出明确提示
- 网络异常时，连接终端是否有失败提示
- token 失效后再次发起授权时，是否能自动恢复并继续完成流程

预期结果：

- 异常场景下应有明确反馈
- 不应出现卡死、无响应或无法恢复的错误状态

## 已知说明

- 当前版本采取“隐藏入口、保留底层实现”的策略，便于后续逐项恢复能力。
- 鸿蒙 `release` 签名包主要用于发布分发，不建议直接按 debug 调试包的方式在真机上本地侧载验证。
- 如需进行真机本地安装联调，建议单独使用 debug 签名包进行测试。
