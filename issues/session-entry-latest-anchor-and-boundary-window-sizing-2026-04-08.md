# 会话页首屏最新锚定与边界窗口大小修复

日期：2026-04-08

## 本轮确认的问题

1. 详情页仍会偶发 `child == _child` 断言。
2. 进入会话页时，并没有稳定地“直接落在最新消息”。
3. 到顶 / 到底仍然偏卡，边界跳转窗口过大且附带不必要动画。

## 根因

### 1. 消息列表里仍残留 turn 级别的 `GlobalKey`

- 即使消息行上的 `GlobalKey` 已移除，turn section / reply anchor 仍在用 `GlobalKey`
- 详情页首屏为了等待滚到底部，之前会在“隐藏列表 + 显示列表”之间切换树形结构
- 大列表 + `GlobalKey` + reparent，仍可能继续触发框架 ownership 断言

### 2. 首屏等待滚底时改变了列表父层结构

- 首屏未 ready 时，build 返回的是 `Stack(hidden list + spinner)`
- ready 后，build 直接返回 `list`
- 这会让同一批消息节点在首屏阶段发生父层结构变化，不利于 element 稳定复用

### 3. 默认窗口和边界跳转窗口偏大

- 默认自动窗口 `160`
- resident 窗口 `480`
- 到顶 / 到底时加载边界窗口默认直接走 resident 大小
- 这会把边界跳转变成一次较重的数据替换和渲染重建

### 4. 边界跳转后仍有动画尾巴

- 到顶 / 到底在边界窗口切换后还会继续跑一次动画
- 对超长消息列表来说，这段动画没有收益，只会增加卡顿体感

## 修复

1. 移除消息列表路径里剩余的 `GlobalKey`
   - turn section / turn reply 全部改成轻量 context 注册
2. 首屏保持同一棵列表树
   - 一直保留同一个 list subtree
   - 未 ready 时只做透明度控制和 loading overlay，不再替换父层结构
3. 缩小默认消息窗口
   - 自动窗口 `160 -> 96`
   - resident 窗口 `480 -> 288`
   - archive shift `160 -> 96`
   - 本地 snapshot 窗口同步改成 `96`
4. 到顶 / 到底边界跳转改成小窗口直达
   - 最老 / 最新边界加载改为自动窗口大小，而不是 resident 大窗口
   - 边界装载完成后直接 `jumpTo` 目标位置，不再附加尾部动画

## 目标效果

- 进入大会话时，默认只恢复更小的一段最新消息
- 详情页首屏直接落在最新消息，不再先看到窗口顶部
- 到顶 / 到底是边界小窗口直达，不再带着大窗口和附加动画卡一下
- 消息列表路径不再依赖 `GlobalKey`，降低 child ownership 断言风险
